### Fase 1: Startup Rápido (~70% del problema de "no abre bien")

#### [MODIFY] [app.py](file:///c:/Users/PLI INGENIERIA/Desktop/ELIMINADOR POTENTE REVO/SUPREMA DE GASTOS/src/app.py)

**Problema**: La función `background_init()` ejecuta túnel, bot, servidor y monitores **en secuencia**. El túnel tarda 15s bloqueantes.

**Cambios**:
1. Lanzar el servidor Flask **primero** (inmediato, no necesita túnel)
2. Lanzar el túnel en paralelo, sin bloquear
3. Mostrar la GUI como "EN LÍNEA" tan pronto el servidor responda, sin esperar al túnel
4. Abrir el dashboard local inmediatamente (no esperar 2 segundos)

```python
# ANTES: Secuencial (Túnel → Bot → Servidor → Monitores)
def background_init():
    TunnelManager.start_tunnel(port=5050)  # ← BLOQUEA 15s
    ...
    server_thread.start()
    ...
    self.bot_instance.run()

# DESPUÉS: Paralelo (Servidor primero, túnel en paralelo)
def background_init():
    # 1. Servidor INMEDIATO
    server_thread.start()
    
    # 2. Abrir dashboard local ya (sin esperar túnel)
    self.after(500, lambda: webbrowser.open(f"http://{local_ip}:5050/dashboard"))
    
    # 3. Túnel en paralelo (NO bloquea)
    threading.Thread(target=self._start_tunnel_async, daemon=True).start()
    
    # 4. Bot
    self.bot_instance.run()
```

### Fase 2: Servidor y Base de Datos (~25% del rendimiento general)

#### [MODIFY] [database.py](file:///c:/Users/PLI INGENIERIA/Desktop/ELIMINADOR POTENTE REVO/SUPREMA DE GASTOS/src/database.py)

**Problema**: Un solo `threading.Lock()` serializa TODAS las operaciones (lectura y escritura). SQLite con WAL soporta lecturas concurrentes.

**Cambios**:
1. Reemplazar `Lock` con `RLock` (reentrant, permite operaciones anidadas)
2. Separar lock de escritura (`_write_lock`) del de caché (`_cache_lock`)  
3. Eliminar lock en operaciones de lectura pura — WAL lo permite
4. Agregar un endpoint SQL directo para `dashboard-updates` sin cargar todos los gastos

```python
# ANTES: Un solo Lock para todo
self._lock = threading.Lock()

def get_all_expenses(self, include_paid=True):
    with self._lock:  # ← Bloquea LECTURAS de otros hilos
        ...

# DESPUÉS: Lock solo para escritura, lecturas sin lock
self._write_lock = threading.Lock()

def get_expenses(self, ...):
    # Sin lock — WAL permite lecturas concurrentes
    conn = self._get_connection()
    ...
```

**Nuevo método optimizado para el dashboard:**
```python
def get_dashboard_summary(self) -> dict:
    """Retorna stats del dashboard con una sola query SQL, sin cargar todos los gastos."""
    conn = self._get_connection()
    row = conn.execute('''
        SELECT 
            COUNT(*) as count,
            COALESCE(SUM(total), 0) as total,
            COALESCE(SUM(CASE WHEN type='Deuda' AND status='pending' THEN total ELSE 0 END), 0) as debt,
            COALESCE(SUM(CASE WHEN type='Prestamo' AND status='pending' THEN total ELSE 0 END), 0) as loan
        FROM expenses
    ''').fetchone()
    return dict(row)
```

#### [MODIFY] [dashboard.py](file:///c:/Users/PLI INGENIERIA/Desktop/ELIMINADOR POTENTE REVO/SUPREMA DE GASTOS/src/dashboard.py)

**Problemas**:
1. TailwindCSS CDN descarga **~300KB en cada carga** (no se cachea)
2. 4 CDNs bloqueantes (Tailwind, Chart.js, html2canvas, Google Fonts)
3. Funciones JS duplicadas (`fetchDashboardUpdates`, `toggleTheme`, `updateThemeIcon`, `sendDashboardToTelegram`)
4. El HTML se genera server-side con f-strings de Python (1160 líneas)

**Cambios**:

2. **Eliminar funciones JS duplicadas** (líneas 912-956 son copia exacta de 1082-1126)
3. **Agregar `font-display: swap`** a Google Fonts para evitar FOIT (Flash of Invisible Text)
4. **Agregar preconnect** a CDNs para acelerar DNS resolution

```html
<!-- ANTES: Scripts bloqueantes -->
<script src="https://cdn.tailwindcss.com?plugins=forms,container-queries"></script>
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>

<!-- DESPUÉS: No bloqueantes donde es posible -->
<script src="https://cdn.tailwindcss.com?plugins=forms,container-queries"></script>
<script defer src="https://cdn.jsdelivr.net/npm/chart.js"></script>
<script defer src="/static/html2canvas.min.js"></script>
<!-- liquidGL.js ya no se usa (comentado en L1137), ELIMINARLO del <head> -->

<!-- Preconnects para acelerar CDN -->
<link rel="preconnect" href="https://cdn.tailwindcss.com">
<link rel="preconnect" href="https://cdn.jsdelivr.net">
```

5. **Eliminar carga de `liquidGL.js`**: Ya está deshabilitado (comentado en línea 1137), pero sigue cargándose en el `<head>` (67KB desperdiciados)
